# Drawer inventory — handoff v4: verification tool exists, next is a static browse page

Goal of the project: turn `20260903_165847.mp4` (a 6m36s pan across cabinets of electronic
component drawers, plus a shelf of SMD resistor reels) into a structured, verified list of
what each drawer holds.

Supersedes `HANDOFF3.md` (data pipeline details, known weaknesses) which supersedes
`HANDOFF2.md` / `handoff.md` (video facts, keyframes, OCR). Not repeated here.

## ⚠️ Read this first

- **Do NOT load the `claude-api` skill.** It auto-triggers on "Claude", "OCR", "vision model"
  and dumps ~100k tokens into context. Nothing here uses the Anthropic API.
- **Do NOT invoke the `claude` CLI as a subprocess** (user instruction).
- User preferences: `uv` for Python (venv at `.venv/`), `rg` not `grep`/`find`, ask if intent
  is unclear, plan before building non-trivial things. Tools are for internal/quick use —

### Entry schema additions since v3 (`inventory.json`)

- `items`: list of `{label, category, description?}` when a label lists several distinct
  parts (254 entries; e.g. `KM4164B / TMS4256 / DRAM` → two DRAM items; `7805 7809 / 7808 7812`
  → four regulators; power-resistor column labels → one item per value). Detected by
  `split_items()` in `categorize.py`; adds review flag `multi-item`. Suffixes like `P-25`
  are folded into the preceding part; a part ending in `-` joins the next line
  (`MAX6383- / XR16D3` = one ordering code MAX6383XR16D3).
- `note` now also used for: label marked uncertain by its owner (`MAYBE!`, `?`) and
  resistor values outside E24/E96 (possible OCR misread; confidence dropped to medium).
- Per-part descriptions (`PDESC`) now override a grouped rule's shared description when the
  shared text mentions several parts or a part not on the label (fixed "XR2211 … LM567"
  on both drawers, "6116" text on the AM29700 drawer, etc.).

### `verify.json` edit record

```json
"7500Ω|19.6": {"status": "wrong", "lines": ["7.5KΩ"], "edited_at": "2026-09-04T12:08:03"}
"1MΩMULTITURN/TRIMPOT|11.7": {"status": "duplicate", "same_as": 49, ...}
"KLEMMUFFER|1.0": {"status": "ok", "contents": [{"label": "M3 screws", "category": "Screw/bolt"}], ...}
```

Fields, all optional: `status` (`ok | wrong | not_drawer | duplicate | unsure`), `lines`,
`category`, `note`, `same_as` (entry `id` = index into inventory + boxes, same order as
`tool.py`/`export_verified.py` assign), `contents` (human item list; overrides auto `items`),
`edited_at`. User's convention: `wrong` = "OCR misread, I corrected the lines" (the entry is
still a real drawer), not "bad entry".

### Verification tool (`tool.py`, `tool.html`)

- `.venv/bin/python tool.py [--port 8765]` → http://127.0.0.1:8765/. Stdlib only; Vue 3
  from jsdelivr CDN. Serves frames from disk, saves each edit immediately to `verify.json`.
- Three columns: filterable queue (flags first, low confidence, then video time), zoomable
  full keyframe with prev/next frame, edit panel (lines, category datalist, status buttons,
  same-as with same-part_key candidates, auto items with "copy to contents", contents
  rows, note). Keyboard: `j/k a w x u d m [ ] e /`.
- If "address already in use": a previous instance is still running (`pkill -f tool.py`).

### Export (`work/export_verified.py`, run from `work/`)

Applies edits (originals kept under `ocr`), drops `not_drawer`, collapses `duplicate` into
`same_as` target (adds `also_seen_at`, merges frames), sets `category_source: human` on
human categories, `contents` = human contents or auto `items`. Output `inventory_verified.json`
`{"inventory": [...sorted by t_first...], "unreviewed": [ids]}` and `inventory_verified.md`.
Every entry has `human: {status, edited_at?, same_as?}`; `status` is `""` if unreviewed.

## Next task: a static browse page for the full inventory

User's words: *"a static webpage for browsing the full inventory — static meaning easy to
host, not that it is not dynamic at all. Use Vue again."*

So: a self-contained page (or page + one JSON) that can be dropped on any static host
(GitHub Pages, a NAS folder, `python -m http.server`), no server-side code. Vue 3 via CDN
`<script>` tag as in `tool.html` (no build step) is the established pattern.

### What the data supports (design from this, confirm with the user first)

- **Source**: `inventory_verified.json` from the export (not `inventory.json`), so the
  page reflects human edits, collapsed duplicates and dropped non-drawers. Decide whether to
  embed the JSON in the HTML (single file, ~1 MB) or load it with `fetch` (two files; needs
  http, `file://` won't work). Embedding is the simplest to host.
- **Browsing**: search across `lines`, `part_key`, `description`, `contents[].label`;
  category filter (list of ~130 categories with counts, like the top of `inventory.md`);
  kind filter; group-by-category view and a flat table view; sort by category / value /
  time. Resistor/capacitor values sort numerically if `parse_r`-style parsing is ported
  to JS (categorize.py has the Python).
- **Per entry**: label lines, category, description, note, contents/items, status badge
  (verified / unreviewed / corrected), `also_seen_at`. Position is not wanted — do not
  show cabinet/row/col beyond `t_first` as a rough "where in the video" hint, if at all.
- **Images**: the frames are 201 MB and local. Options: (a) no images; (b) generate
  downscaled frames (e.g. 400 px wide ≈ 30 KB × 529 ≈ 16 MB) into `frames_small/` with
  Pillow/OpenCV (venv has `opencv-python-headless`) and link `frames[0]`; (c) only for
  verified entries. Ask the user; (a) or (b) are both plausible for "easy to host".
- **Regeneration**: a small script (`work/build_site.py`) that runs the export and writes
  `site/index.html` (embedding the JSON) is what keeps it repeatable as verification
  continues. The page should not require re-touching HTML when data changes.

### Questions to ask before building

1. Single-file HTML with embedded data, or HTML + JSON?
2. Images: none / downscaled keyframes / only for verified entries?
3. Should unreviewed entries be shown (with a badge) or only verified ones? (At 93/1356
   verified, hiding unreviewed makes the page nearly empty for now.)
4. Where will it be hosted (affects whether `fetch` and relative paths are fine)?

## Reproduce / extend

```bash
cd /home/jas/dev/tests/drawers/work
../.venv/bin/python dedup3.py           # ~2 s   ocr/*.jsonl → dedup3_out.json
../.venv/bin/python categorize.py       # ~1 s   → ../inventory.json, ../inventory.md, excluded_boxes.json
../.venv/bin/python export_verified.py  # <1 s   + ../verify.json → ../inventory_verified.{json,md}
cd .. && .venv/bin/python tool.py       # verification tool
```

Category rules: `RULES` (ordered), `OVR` (per-key overrides), `PDESC` (per-part
descriptions), `split_items()` / `DESCR` (multi-item detection) in `categorize.py`.
Rerunning `categorize.py` never touches `verify.json`; edits are matched by key, so an entry
whose `part_key` or `t_first` changes after a dedup/rule change would orphan its edit
(check with a quick key diff if `dedup3.py` is ever changed).
